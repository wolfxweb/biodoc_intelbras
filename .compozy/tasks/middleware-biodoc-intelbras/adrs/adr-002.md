# ADR-002: Gerenciamento de Token Persistente para API do Defense IA

## Status

Accepted

## Date

2026-05-16

## Context

A API do Intelbras Defense IA requer autenticação via tokens gerados por um processo de login de múltiplas etapas, conforme encapsulado na biblioteca `defenselib.py`. O middleware precisa validar o acesso e retransmitir eventos do BIODOC para o Defense IA no menor tempo possível (requisito do PRD: tempo real). Precisávamos definir como esse token seria mantido e utilizado no ciclo de vida das requisições.

## Decision

Optamos por utilizar um **Token Persistente em Memória com Keep-Alive**. O middleware realizará o login no Defense IA uma única vez durante a inicialização (startup event) e manterá o token ativo através de uma rotina paralela em background. As requisições de webhook do BIODOC utilizarão esse token que já está em memória para disparar os eventos de imediato.

## Alternatives Considered

### Alternative 1: Login a cada requisição (Síncrono)

- **Description**: Fazer login e obter um novo token do Defense IA no início de cada rota de sincronização.
- **Pros**: Implementação muito simples e "stateless"; sem necessidade de gerenciar threads em background.
- **Cons**: Adiciona centenas de milissegundos de latência à cada requisição; sobrecarrega desnecessariamente a API de autenticação do Defense IA sob alto volume.
- **Why rejected**: A latência e a carga na API de destino degradariam o requisito de liberação instantânea de acesso físico.

## Consequences

### Positive

- Latência mínima: os eventos são despachados sem o overhead do processo criptográfico de login.
- Redução na carga computacional do Intelbras Defense IA e do middleware.

### Negative

- O middleware torna-se stateful (guarda estado do token).
- Requer lógica adicional para re-autenticação automática (re-login) caso a API da Intelbras retorne 401 (token expirado/inválido), seja por queda da API ou perda do keep-alive.

### Risks

- A rotina de keep-alive pode falhar silenciosamente, forçando a primeira requisição útil a falhar. *Mitigação*: O middleware deve capturar erros de autorização do Defense IA, forçar um novo login on-the-fly e tentar novamente a requisição falha antes de retornar erro para o BIODOC.

## Implementation Notes

A biblioteca `defenselib.py` já possui a função `updateToken`, mas será necessário adaptá-la ou controlá-la no ciclo de vida do FastAPI (usando `Lifespan` ou `BackgroundTasks`).
